# Vercel + Turso

Стенд: https://saq-qurylys-one.vercel.app. Production: APP_ENV=production, SAQ_AUTH_MODE=session, SAQ_DEMO_MODE=0. Файловая SQLite на Vercel не используется. База — отдельная Turso, регион функций bom1.

## Новая установка

1. Установить Node 24.x, `npm ci`, выполнить `npm run check`. Создать Vercel-проект, привязать репозиторий/каталог через `vercel link`.
2. Подключить Turso. Сохранить TURSO_DATABASE_URL/TURSO_AUTH_TOKEN в Production env; Preview должен использовать отдельную БД. Задать APP_URL равным HTTPS-адресу сайта. Добавить режимы production/session/0, описанные выше.
3. Подключить нужные сервисы: AI_GATEWAY_API_KEY, AI_GATEWAY_MODEL, DRONE_AI_MODEL; APIFY_TOKEN, CRON_SECRET и APIFY_WEBHOOK_SECRET; TELEGRAM_BOT_TOKEN и TELEGRAM_WEBHOOK_SECRET. Все токены — server-only. Случайные секреты webhook/cron — минимум 32 случайных байта. Неподключённые внешние функции недоступны, текстовые правила работают без ИИ.
4. В защищённой локальной среде с переменными целевой БД выполнить `npm run db:migrate` (схема 6). При желании импортировать исходную публичную выборку командой `npm run db:import`. Не запускать seed для production. Миграции не выполняются автоматически при сборке.
5. Создать первого администратора: `node --import tsx --env-file=.env.local scripts/bootstrap-admin.ts /absolute/private/path/admin.json`. Скрипт откажется заменять существующего пользователя, создаст файл с правами 0600 и проверит вход/выход. Путь должен находиться **вне репозитория**. Пароль передаётся владельцу отдельно, не в Git.
6. `vercel --prod`. Проверить `/api/liveness` (200), анонимный `/api/projects` (401), вход и карточку объекта. Для Telegram выполнить `APP_URL=https://YOUR_DOMAIN npm run telegram:setup`, затем отправить /start и реальное тестовое сообщение боту.

`npm run users -- create LOGIN NAME admin|analyst|viewer` принимает пароль только через stdin. `npm run users -- disable LOGIN` отзывает доступ и сессии. Администратор управляет платным сбором, аналитик — проверками и объектами, наблюдатель — чтением. SSO/MFA пока нет.

## Работа сборщика

vercel.json задаёт Cron `0 12 * * *` (12:00 UTC), API защищено CRON_SECRET. На действующем Hobby используется ежедневный запуск, не поминутный мониторинг. Завершение Apify вызывает защищённый webhook; сервер повторно читает результат по сохранённому run_id и продолжает очередь. Один цикл проверяет до трёх запусков и стартует максимум один новый. Лимит $1/24 ч учитывается в БД; неизвестный исход платного запроса не запускается повторно автоматически.

Не запускайте параллельно локальный worker с копией production-БД: бюджеты независимы. Очередь, журнал, ошибки площадок и время последнего запуска доступны в /monitoring. Выдача публичных публикаций не гарантирует полный охват рекламы.

## Обновление и откат

GitHub Actions проверяет код без production-секретов. Действующий стенд публикуется CLI; GitHub auto-deploy не настроен. После зелёных проверок, резервной копии и совместимых миграций выполнить `vercel --prod`. Изменение env требует нового deployment. Перед переключением убедиться в правильности проекта и команды Vercel.

Для отката используйте предыдущий проверенный deployment Vercel. Откат кода не откатывает схему: не запускайте несовместимую старую версию на новой БД. Восстановление данных — отдельная процедура Turso, сначала в отдельную базу. `scripts/backup.ts` предназначен только для локальной SQLite, не заменяет облачный backup.

## Эксплуатационные проверки

- HTTP: /api/liveness; БД и приложение: /api/health после входа.
- Telegram: getWebhookInfo, отсутствие очереди ошибок, тестовый текст/скриншот.
- ИИ: доступ к модели и кредиты; невалидный ответ или ошибка не должны превращаться в «низкий риск».
- Apify: бюджет, свежесть очереди и последние ошибки каждой площадки.
- Бэкапы: назначить ответственного, настроить экспорт/восстановление Turso и провести учебное восстановление. Пока оно не подтверждено.

Автоматические государственные реестры и распознавание речи не подключены. Есть OCR скриншотов и наблюдения по снимкам стройки. Результат — приоритет проверки, не вывод о нарушении.
