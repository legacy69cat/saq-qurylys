# Запуск пилота на сервере

Один сервер Linux с Docker Compose, постоянным диском и доменом. Запускайте один worker. Блокировка в SQLite отклоняет второй процесс; после аварии блокировка истекает через 5 минут. Это не распределённая очередь и не гарантия exactly-once внешних запросов. SQLite не размещать на сетевой файловой системе. Конфигурация не является подтверждением успешного развёртывания.

1. Скопировать `production.env.example` в `production.env`, заполнить домен и ключ Apify; права файла `chmod 600 production.env`. AI Gateway можно оставить пустым: правила продолжают работать, ИИ недоступен. Направить DNS домена на сервер; открыть 80/443. Порт 3000 наружу не публикуется.
2. Из каталога deploy: `docker compose build` затем `docker compose run --rm migrate`.
3. Создать администратора, передавая пароль через stdin (не через аргументы и не записывая в историю). В bash:

```bash
read -rs -p 'Password: ' SAQ_PASSWORD
printf '%s' "$SAQ_PASSWORD" | docker compose run --rm -T web node --import tsx scripts/users.ts create admin 'Администратор' admin
unset SAQ_PASSWORD
```

Аналогично роли `analyst` и `viewer`. Минимум 14 символов. Общих учётных записей не использовать. Отзыв доступа: `docker compose run --rm web node --import tsx scripts/users.ts disable LOGIN`. Пароли хранятся в виде scrypt-хешей; сессии истекают через 8 часов. Роль admin управляет платным сбором, analyst — проверками и объектами, viewer — только просмотром. Автор действий берётся из сессии. SSO/MFA и интерфейс управления пользователями ещё не реализованы.

4. `docker compose up -d`. Caddy получает TLS-сертификат. Проверить HTTPS, вход, отсутствие данных у анонимного клиента, роли, worker и расход Apify. Лимит сбора сохраняется $1/24 часа; очередь может ждать бюджета. Полнота выдачи соцсетей не гарантируется.
5. Резервная копия: `docker compose exec web node --import tsx scripts/backup.ts`. Команда создаёт согласованный снимок SQLite и проверяет integrity_check. Настроить ежедневный запуск средствами сервера, перенос зашифрованной копии на независимое хранилище и контроль ошибок. Сам Docker volume не защищает от потери сервера.
6. Для восстановления остановить web/worker, сохранить текущую БД и WAL/SHM, восстановить снимок в отдельный каталог, проверить `PRAGMA integrity_check`, назначить владельца UID 1000, переключить DATABASE_PATH. Не заменять файл работающей SQLite. Проверить вход, число объектов и очередь до возобновления сборщика. Провести учебное восстановление до допуска пользователей.

`/api/liveness` сообщает только доступность HTTP. `/api/health` требует входа. Следите отдельно за свежестью worker, ошибками платформ, бюджетом, свободным диском и резервными копиями. Перед обновлением делать снимок; откат схемы — восстановлением снимка, не запуском старого приложения на новой схеме.

До публичной эксплуатации необходимы: выбранный сервер/домен, подтверждённый бюджет, реальные персональные учётные записи, проверка TLS и восстановление резервной копии на целевом сервере. Нужны отдельная политика хранения публикаций и ограничение доступа к персональным данным. OCR скриншотов поддерживается; распознавание речи отсутствует; скоринг текста — приоритет проверки, не установленное нарушение.
