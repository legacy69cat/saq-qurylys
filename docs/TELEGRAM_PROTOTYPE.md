# Первый сценарий проверки для жителя

1. Человек присылает текст объявления. Для фото, скриншота или видео сначала требуется извлечение текста; пока оно не подключено, бот сообщает, что оценки недостаточно, и предлагает прислать описание. Одна ссылка тоже не считается содержимым объявления.
2. После распознавания человек видит извлечённый текст и может исправить его до проверки. Исходное объявление рассматривается как данные, а не инструкции для модели.
3. Общий модуль `buildAdReport` возвращает предварительные признаки R2/R3, дословные цитаты, сумму до 35 баллов и перечень непроверенных факторов. `fullRisk: null` означает отсутствие полной оценки; ноль текстовых баллов не означает безопасность. Нельзя представлять балл как вероятность мошенничества.
4. Человек получает краткий ответ `formatAdReport` и может проверить другое объявление. Нет автоматического создания объекта на карте, подтверждения нарушения или отправки материалов в департамент.
5. Перед передачей материалов аналитику нужен отдельный пользовательский шаг с понятным описанием получателя и сохраняемых данных. Для MVP такую передачу не включать без готового процесса обработки.

Реализована подготовка: общий тип отчёта, текстовый формат ответа и закрытый экран `/check`, где можно пройти сценарий с текстом. В браузере введённые материалы не сохраняются на сервере. Telegram-бот ещё не подключён.

Для следующего этапа: токен BotFather в защищённой переменной, проверяемый секрет webhook, учёт обработанных update_id, лимиты пользователей и размера файлов, ограниченный срок хранения, безопасное скачивание файлов только через Telegram API, распознавание изображений и явное сообщение об ошибках распознавания. Ни текстовые команды из объявления, ни подписи к файлам не должны менять правила скоринга. Перед публичным запуском отдельно проверить повторную доставку, превышение лимитов и удаление данных.
