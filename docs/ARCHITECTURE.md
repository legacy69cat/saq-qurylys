# Архитектура SAQ QURYLYS

Актуальное описание конкурсного прототипа. Команды запуска и ограничения: [README](../README.md). Проверки требований: [матрица кейса](CASE_MATRIX.md).

## Приложение и хранение

Единое приложение Next.js / React / TypeScript развёрнуто на Vercel. Страницы и серверные действия работают с общим асинхронным интерфейсом БД: локально — SQLite, в облаке — Turso. Схема обновляется миграциями; текущая версия — 7. Production требует серверные сессии, локальный режим без входа предназначен для разработки.

| Слой | Ответственность |
|---|---|
| `src/domain` | Расчёт R1–R6, предварительные текстовые признаки, валидация цитат, адреса и сценарные оценки |
| `src/server/db` | Миграции, транзакции, источники, решения, версии сигналов и журнал |
| `src/server/ai` | AI Gateway: гипотезы R2/R3, OCR и визуальные наблюдения |
| `src/server/social` | Планирование, бюджет, вызовы Apify, постраничный импорт и дедупликация |
| `src/server/registries` | Поиск Homeportal/eQurylys и сохранение результатов с источниками |
| `src/server/telegram` | Webhook, лимиты, защита от повторных updates, отчёт и очередь обращений |
| `src/server/auth` | Пароли scrypt, серверные сессии, роли admin/analyst/viewer |
| `src/app`, `src/components` | Интерфейс и точки входа; серверные операции проверяют доступ |

## Публикация → подтверждённый риск

1. Apify возвращает публикации в `collected_posts`; ручной ввод сохраняет публикацию непосредственно в карточку ЖК.
2. Для собранной публикации система предлагает кандидатов ЖК, но совпадение подтверждает человек. Автопривязки нет.
3. Модель предлагает цитируемые гипотезы R2/R3. Ответ проверяется по структуре, наличию цитаты и контексту отрицаний.
4. Гипотезы хранятся отдельно от подтверждённых факторов. Принятие решения фиксирует автора, время и связанные материалы.
5. Чистая функция `calculateRisk` пересчитывает балл при чтении. Она не вызывает модель. Неизвестные данные и повторы не добавляют вес.
6. Сигнал сохраняет JSON-снимок объекта и SHA-256 отпечаток. Решение проверяет актуальность снимка; после возврата создаётся новая версия.

Вызов модели происходит вне транзакции. Сначала фиксируется запуск, затем результат записывается атомарно. Ошибка провайдера не удаляет исходную публикацию. Уверенность ИИ не является вероятностью нарушения.

## Фоновая работа

На Vercel ежедневный Cron вызывает `/api/cron/collect`; результаты Apify также поступают через защищённый webhook. Локально можно запустить `npm run collect:social`. Очередь резервирует бюджет, хранит статусы и ограничивает импорт 1000 записями за набор.

Неопределённый результат платного запуска не повторяется автоматически: он требует сверки. Повторное чтение результатов допускается; импорт и завершение задания выполняются транзакционно. Полнота выдачи соцсетей не гарантируется.

Homeportal предоставляет кандидатов разрешений/гарантий и опубликованных предупреждений. eQurylys проверяется по точному БИН. Cron обрабатывает до шести давно не проверенных реальных объектов. Эти результаты не подтверждают R1 автоматически. Для демонстрационных ЖК внешние проверки отключены.

## Telegram и изображения

Webhook проверяет секрет и принимает личные сообщения. Обращение сохраняется до OCR; при ошибке распознавания остаётся запись о полученном снимке. Повторный update не создаёт второе обращение.

В `telegram_inbox` сохраняются текст/OCR, статус и последнее решение. Привязка обращения к ЖК и перенос публикации выполняются вручную. Нет автоматического ответа с итоговым решением, полной истории редактирования обращения и durable outbox доставки. При сетевом сбое возможен повтор ответа.

Для OCR и дрона используются предобученные модели через Gateway. Исходные фотографии в базе приложения не хранятся. Текст OCR требует сверки; наблюдения дрона не устанавливают законность строительства.

## Три разных режима данных

- **Фактические данные:** публичная выборка объектов и сохранённые материалы; риск начисляется только по подтверждениям.
- **Изолированное демо:** `npm run demo` создаёт временные 8 вымышленных ЖК / 12 публикаций. Облачная БД, Telegram и сбор отключены; допускается полный изменяющий данные сценарий.
- **Симуляция на карте:** `/?simulation=1` накладывает условные наборы R1–R6 на реальные координаты только при отображении. Карточка сценария доступна для чтения; расчёт не сохраняется в факторы и сигналы. Выбор режима хранится в cookie 7 дней; `/?simulation=0` возвращает фактические данные. API объектов возвращает фактические оценки.

`SAQ_SHOW_SIMULATIONS` — отдельная настройка видимости вымышленных записей в рабочем реестре, по умолчанию выключена. Это не включение сценарного скоринга.

## Границы эксплуатации

Секреты остаются на сервере, webhook защищены, права на запись проверяются сервером. Внешние адаптеры используют заданные хосты и ограничения ввода. При этом нагрузочная приёмка, SSO/MFA, регламент хранения обращений и проверенное аварийное восстановление БД остаются следующими этапами. Успешный CI проверяет приложение с изолированными данными, а не доступность внешних сервисов.
