# Telegram: проверка объявления

Прототип для личной переписки. Отправьте /start, затем текст объявления либо один скриншот как фото (до 5 МБ). OCR через DRONE_AI_MODEL распознаёт текст; итоговый предварительный балл считает общий buildAdReport, как на странице /check. Подпись к фото включается в проверку. Бот показывает распознанный текст (фрагмент до 1800 символов), цитаты, R2/R3 и непроверенные факторы. Полный риск и законность объекта не определяются. Ссылки не скачиваются, документы, видео и голосовые не поддерживаются.

## Подключение

1. Создать бота в @BotFather. Сохранить TELEGRAM_BOT_TOKEN в .env.local, не в Git.
2. Сгенерировать TELEGRAM_WEBHOOK_SECRET (случайные 32 байта hex), сохранить локально и вместе с токеном в Production env Vercel.
3. Проверить APP_URL, AI_GATEWAY_API_KEY, DRONE_AI_MODEL; опубликовать deployment.
4. С теми же переменными выполнить `node --import tsx --env-file=.env.local scripts/setup-telegram.ts`. APP_URL должен указывать на production. Скрипт устанавливает команды и защищённый webhook, не удаляет ожидающие обновления.
5. Открыть ссылку бота, отправить /start, затем текст и скриншот. getWebhookInfo сам по себе не проверяет доставку сообщения.

## Ограничения прототипа

Webhook проверяет секрет Telegram до обработки. Только личные чаты. Лимиты: 10 обновлений/час на чат, 100/сутки на бот (включая команды), входящий JSON до 64 КБ, изображение до 5 МБ/40 МП. Лимиты хранятся в Turso, а не в памяти процесса. Используется auth_throttle с отдельным префиксом telegram; миграция не нужна.

Текст объявления и распознанный текст снимка сохраняются в очереди `/inbox` для аналитика. Исходные снимки в базе SAQ не сохраняются. Очередь содержит идентификатор обращения, время получения, статус, комментарий и автора последнего решения; имя и chat_id отправителя в очередь не копируются. Автоматическая отправка решения аналитика в Telegram пока не выполняется. Сохраняются технические идентификаторы обновлений/чатов и счётчики; истёкшие записи очищаются при запросах через 7 дней. Telegram и провайдер ИИ обрабатывают содержимое по своим условиям. Не отправляйте персональные документы. Секреты и тела сообщений не логируются приложением.

Обновления дедуплицируются; незавершённая обработка получает временную блокировку. Telegram повторяет неуспешную доставку. В редком случае сбоя после отправки ответа, но до записи завершения возможен повтор ответа; строгая exactly-once доставка не гарантируется. Постоянная очередь и история обращений отсутствуют. OCR может неверно прочитать числа/отрицания: пользователь должен сверить текст; 0 баллов не доказывает безопасность.

## Единый результат с сайтом

Страница /check теперь тоже принимает скриншот (до 3 МБ). Общая функция recognizeAdPhoto распознаёт текст, общие buildAdReport/formatAdReport вычисляют и объясняют баллы. На сайте перед оценкой требуется проверить/исправить распознанный текст. В боте оценка автоматическая с явной пометкой OCR. Число баллов не отображается как «35 из 35», чтобы не создавать впечатления максимального риска. Непроверенные реестры по-прежнему не подменяются выводами модели.
