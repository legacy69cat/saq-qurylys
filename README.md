# SAQ QURYLYS

Локальная рабочая версия для аналитика: объединяет сведения о ЖК, рекламу и доказательства, рассчитывает объяснимый приоритет проверки и сохраняет решение человека в сигнальной карточке.

## Реализовано

- Дашборд и интерактивная карта OpenStreetMap / Leaflet. Начальная выборка — 12 строящихся ЖК Усть-Каменогорска из публичных карточек Krisha.kz, с адресами, координатами, URL и датой фиксации. Это не полный реестр города и не официальная проверка правового основания.
- Добавление объектов с источником; привязка собранной публикации после проверки совпадения. Неизвестный БИН отображается явно, баллы без подтверждения не начисляются.
- Карточка ЖК: застройщик/БИН, стадия, готовность, правовое основание, автор и время проверки, публикации с площадкой, аккаунтом, датой и сохранённым текстом.
- Ручной ввод новой публикации с явной привязкой к открытому ЖК. URL сохраняется, но сервер не загружает его содержимое.
- ИИ-адаптер Vercel AI Gateway / AI SDK: анализ нового текста, гипотезы R2/R3, дословная цитата, объяснение и уверенность модели. Реальный вызов требует локального ключа и модели.
- Ручные гипотезы при недоступном ИИ; подтверждение/отклонение аналитиком. До подтверждения балл не меняется.
- Ручная проверка основания с сохранением ссылки, результата, автора и времени; справочник 11 источников РК. Отсутствие записи в поиске не превращается в R1.
- Ручная проверка R4/R6 с документом; R5 требует двух оценок готовности с источниками, датами и расхождением от 20 п.п. Есть отмена начисления R4–R6 с сохранением истории.
- Детерминированный скоринг R1–R6, источники у подтверждённых факторов и гипотез, история действий.
- Версии сигнальной карточки: ожидание проверки → подтверждение или возврат с обязательным комментарием. Снимок материалов не изменяется; после возврата можно подать следующую версию. Устаревший сигнал нельзя подтвердить.
- Печатная версия с материалами, баллом, зоной, статусом, автором и датами; кнопка «Печать / сохранить PDF» использует печать браузера.

## Быстрый запуск

Требуются Node.js **24.15+ ветки 24.x** (см. `.nvmrc`) и npm. SQLite встроена в Node.

```bash
npm ci
cp .env.example .env.local
npm run db:setup
npm run db:import
npm run dev
```

Открыть http://127.0.0.1:3000. Для существующей установки не перезаписывайте `.env.local`; после обновления выполните `npm run db:setup`, чтобы применить миграции до версии 5. Миграции не удаляют существующие данные. `db:setup` больше не создаёт демонстрационные объекты. `db:import` импортирует подготовленный файл `data/real-projects.json`, не обновляя существующие карточки.

```bash
npm run build
npm start
```

Приложение слушает только `127.0.0.1`. Это однопользовательское локальное приложение: имя автора вводится вручную и **не является аутентификацией**. Не публикуйте эту сборку в сеть без добавления авторизации и контроля доступа. Облачный деплой не выполнен.

`DATABASE_PATH` задаёт путь к SQLite, по умолчанию `./data/saq.sqlite`. Файл не входит в Git. Доступны `db:migrate`, `db:seed`, `db:setup`. При неподготовленной или старой схеме интерфейс предлагает `npm run db:setup`, API возвращает 503.

## Автоматический сбор соцсетей

1. Добавьте серверный `APIFY_TOKEN` из Apify Console → API & Integrations в `.env.local`. Это отдельный ключ, не `AI_GATEWAY_API_KEY`.
2. Выполните `npm run db:setup` и перезапустите сайт.
3. В отдельном терминале из папки проекта запустите `npm run collect:social`. Для одного цикла: `npm run collect:social -- --once`.
4. Откройте `/monitoring`, сохраните город, поисковую фразу, площадку, лимит и интервал. «Собрать сейчас» ставит одно задание в очередь; «Включить расписание» включает регулярный сбор.

Работает только пока запущен отдельный процесс сборщика и компьютер доступен. Закрытие вкладки не останавливает сбор. При остановке процесса/сне компьютера задания остаются в SQLite; после запуска выполняется один пропущенный сбор, без накопления всех пропущенных интервалов. Фоновый сервис ОС/облачный деплой не настроен. Сайт показывает время активности сборщика и обновляет ленту каждые 15 секунд, пока вкладка видна и пользователь не редактирует форму.

Адаптеры: `clockworks/tiktok-scraper` (поиск видео), `coregent/facebook-search-scraper` (публичные посты), `apify/instagram-search-scraper` (популярные Reels). Город добавляется к фразе, а не используется как доказанная геолокация. Instagram запрещает часть знаков в запросе: они заменяются пробелами при отправке, исходное название города хранится неизменным. Не всякая фраза имеет выдачу Reels; `no_items` показывается явно. Это не полная рекламная библиотека площадок. Медиа, комментарии и контакты не сохраняются в локальной ленте; распознавание видео не выполняется.

Наборы RU/KZ: 48 фраз в 6 группах, по 8 фраз в пакете. Каждая группа создаёт 3 поиска (TikTok/Facebook/Instagram), повторная установка не создаёт дубли. Для Усть-Каменогорска запросы чередуют три написания города; на других городах используется введённое имя. В ручном поиске фразы разделяются символом `|` (до 8). Лимит результатов делится между фразами целыми долями, остаток не используется. Каталог и управление находятся в `/monitoring`, учебный сценарий — `/analyst-guide` и `docs/ANALYST_SCENARIO.md`. Слова об оплате в ленте — только лексические подсказки, без изменения скоринга.

Лимит — от числа фраз до 50 записей за запуск. API получает ограничение расходов $0,50 для TikTok (его минимальный допустимый лимит) и $0,20 для остальных; тайм-аут запуска 300 секунд. Общий бюджет резервируемых запусков — $1 за скользящие 24 часа на эту SQLite. Фактические расходы отражает Apify, тарифы могут измениться. Ограничение относится только к запускам этого приложения, не к действиям в Apify Console. Отвергнутые до запуска запросы не занимают бюджет, неоднозначные сетевые сбои продолжают его занимать. Один активный запуск на поиск; неясный результат POST не повторяется автоматически и требует сверки в Apify Console. Безопасные чтения результатов повторяются сборщиком.

Публикации дедуплицируются по площадке и идентификатору, первое сохранённое содержимое не перезаписывается. Хранятся совпадения со всеми поисками/запусками, автор, URL оригинала, дата публикации (если предоставлена), время обнаружения. Отсутствующая дата не заменяется временем сбора. Доступны фильтры площадки/города, архив и постраничная лента. Данные выводятся как текст, ссылки проверяются по домену и типу публикации. Сбор не привязывает записи к ЖК и не подтверждает R1–R6.

В локальной БД для Усть-Каменогорска включены все 18 пакетных поисков раз в неделю, до 40 результатов за запуск; прежние 3 одиночных поиска сохранены на паузе. Бюджет не увеличен: полный цикл имеет верхнюю сумму резервов $5,40 и при ограничении $1/24 ч займёт несколько дней. Новые пакеты прошли API-валидацию Apify; получение результатов зависит от очереди, бюджета и доступности источников. Пауза расписания запрещает новые плановые задания, но не отменяет уже поставленные в очередь/запущенные задания.

## Настройка ИИ

1. Создайте ключ в [Vercel AI Gateway](https://vercel.com/docs/ai-gateway/getting-started).
2. В локальном, исключённом из Git `.env.local` заполните `AI_GATEWAY_API_KEY`.
3. Укажите `AI_GATEWAY_MODEL` — точный `provider/model` из [текущего каталога](https://ai-gateway.vercel.sh/v1/models), поддерживающий текст и structured output.
4. Перезапустите сервер. Откройте публикацию и нажмите «Запустить ИИ-анализ».

В локальном окружении разработки 18 октября 2026 выбран `google/gemini-3.8-flash`: он присутствовал в каталоге и поддерживал structured output. `.env.example` намеренно не закрепляет меняющийся модельный ID. Выбор можно заменить без изменения кода.

Только по действию аналитика текст публикации и название ЖК передаются через Gateway выбранному провайдеру; запросы могут расходовать средства аккаунта. Лимит входного текста — 12 000 символов, тайм-аут — 30 секунд, автоматических повторов нет. По успешно завершённому анализу повторный запрос этой неизменяемой публикации не выполняется. Прерванный запуск можно повторить через 2 минуты.

Ответ модели проходит структурную проверку и проверку точного вхождения цитаты в исходный текст. Допустимы только R2/R3. Инструкции внутри рекламы считаются недоверенными данными. Пустой список гипотез не означает отсутствие риска. Уверенность — оценка модели, не вероятность установленного нарушения; выводы ниже 70% отмечены как неуверенные. Все гипотезы требуют решения человека независимо от уверенности.

Без ключа ручной сценарий работает целиком. Ошибка/тайм-аут ИИ не удаляет публикацию и не начисляет баллы. Модель не устанавливает правовой статус, не принимает решение по сигналу и не отправляет материалы в госорганы.

### Живая оценка модели

```bash
npm run test:ai:live
```

Команда выполняет 7 реальных запросов через настроенный аккаунт: платная/бесплатная бронь, депозит, обычная реклама, неопределённые условия, отрицание и prompt injection. Она выводит ожидаемые/полученные коды, цитаты и итог. Это малый учебный набор, а не измерение качества на реальном корпусе. Без ключа команда завершается до сетевых запросов.

Обычные `npm test` и E2E не тратят кредиты и не обращаются к модели. Транспорт ИИ в модульных тестах заменён тестовым ответом; это проверка адаптера, не доказательство качества модели. В текущей среде ключ не настроен, поэтому живая оценка **ещё не выполнена**.

## Демонстрация сквозного сценария

1. Открыть «Контур 07»: только R1, 35 баллов, жёлтая зона.
2. Ввести публикацию: «Контур 07 строится. Внесите депозит 300 000 ₸ за квартиру». Указать учебную площадку, аккаунт, ссылку, дату и автора.
3. Выполнить ИИ-анализ с настроенным ключом. Без ключа явно использовать «Добавить гипотезу вручную»: отдельно R2 с цитатой «Внесите депозит 300 000 ₸» и R3 с цитатой «Контур 07 строится.».
4. Показать неизменный балл до подтверждения. Подтвердить R2 и R3: 70 баллов, красная зона; показать источники и историю.
5. Создать сигнал. Вернуть с причиной, создать версию 2 и подтвердить её. После перезагрузки решение сохраняется.
6. Открыть печать, выбрать сохранение PDF. На отчёте видны статус, версия, автор, даты, балл, факторы, материалы и маркировка демо.
7. Показать «Контур 01» — A=35/жёлтый; «Контур 02» — B=70/красный; «Контур 03» — C=10/зелёный.

Решение по конкретной гипотезе окончательно: повторная отправка того же решения не дублирует событие, противоположное решение блокируется. Отклонение новой гипотезы не отменяет ранее подтверждённый фактор. Полноценный процесс отзыва ранее подтверждённых рекламных факторов — отдельная будущая функция. Проверка основания может быть обновлена с сохранением истории.

## Источники и данные

Страница `/sources` содержит ссылки, предоставленные для кейса: Homeportal, E-License, Qazreestr, Ashyq Data, eQurylys, eGov, КГД, РСП, кадастровая карта, открытые данные и реестр недобросовестных участников госзакупок. Это справочник для ручной проверки, **не действующие API-интеграции**. Доступность, охват и актуальность каждого источника проверяет аналитик. Сведения о налогах/закупках сами по себе не начисляют R1–R6.

Все исходные ЖК, БИН, обращения и документы вымышлены. `example.invalid` — адреса учебных примеров, а не реальные публикации. Ручной ввод в карточках демо-ЖК остаётся демонстрационным. Отдельная лента `/monitoring` содержит реальные публичные записи от Apify; они не считаются доказанными объявлениями о конкретном ЖК. Даты хранятся в UTC, отображаются в Asia/Almaty; дата публикации без времени хранится как начало дня UTC.

## Проверки

```bash
npm run check       # ESLint, TypeScript, Vitest, production build
npx playwright install chromium
npm run test:e2e    # production build + desktop/mobile Chromium
```

E2E создаёт отдельную временную SQLite, сбрасывает только её перед каждым тестом и удаляет после прогона. Порт 3100 должен быть свободен. AI Gateway и Apify принудительно отключены в браузерных тестах; импорт мониторинга проверяется на явно тестовой записи. Скриншоты, PDF и трассы находятся в `test-results/` (не коммитятся).

Если Chromium Headless Shell на macOS падает при загрузке ICU в GPU-процессе, можно использовать полноценный Chromium:

```bash
npx playwright install chromium --no-shell
PLAYWRIGHT_CHANNEL=chromium npm run test:e2e
```

Проверено 18 октября 2026 на Node.js 24.19.0: **87 модульных/интеграционных тестов, 12 браузерных тестов (desktop/mobile), ESLint, TypeScript и production-сборка — успешно**. Браузерные проверки включают ввод публикации, отсутствие ключа ИИ, ручное подтверждение R2/R3, изменение балла 35 → 70, возврат и вторую версию сигнала, подтверждение, перезагрузку, печать PDF и проверку неизвестного основания. Для macOS использован полноценный Chromium (`PLAYWRIGHT_CHANNEL=chromium`). Живые запросы к ИИ по решению пользователя не выполнялись.

## Архитектура

- `src/domain/risk.ts` — чистый скоринг и зоны.
- `src/domain/analysis.ts` — валидация входных данных, ответов и цитат.
- `src/server/db/` — SQLite, три миграции, seed, транзакции и журнал.
- `src/server/ai/analyze.ts` — серверный Gateway-адаптер и версия промпта.
- `src/server/actions.ts` — Next.js Server Actions для записи и решений; проверка данных на сервере, сообщения об ошибках и обновление страниц.
- `src/app/` — реестр, карточки ЖК, справочник источников, сигналы.
- `tests/` — доменная логика, БД, адаптер ИИ и браузерный сценарий.

Стек: Next.js, React, TypeScript, `node:sqlite`, AI SDK 7, Vitest, Playwright. Версии зафиксированы в lock-файле. При разработке использовались инструменты генерации кода.

Read-only API: `GET /api/projects`, `GET /api/health`. Запись выполняется через Server Actions, а не через эти GET-маршруты. Неизменяемый снимок сигнала хранит объект, текущие факторы, источники и версию правил; статус/решение хранятся отдельно. Изменение текущих данных не переписывает снимок. Перед подтверждением сравнивается отпечаток с актуальными данными.

## Оставшиеся ограничения и сдача

Нет OCR, распознавания речи видео, автоматического сопоставления ЖК, реальных государственных интеграций и авторизации. R4–R6 демонстрируются на seed; отдельных форм ввода обращений и оценок готовности пока нет. Реальные вызовы ИИ требуют ключа и проверки выбранной модели. CI-шаблон есть в `docs/examples/github-actions-ci.yml`, автоматический workflow не включён.

Последняя подтверждённая видимость GitHub — PRIVATE (проверка 15 октября 2026); публичность в рамках доработки не менялась. Перед сдачей нужен публичный репозиторий, фиксированный SHA и проверка доступа жюри. Питч и резервная запись не подготовлены. Рекомендуемая отсечка в кейсе — 20 октября 2026, 23:59; часовой пояс уточняется у организаторов.

## Реестр без демонстрационных данных

Демонстрационный seed оставлен только для разработки и изолированных тестов: явный `npm run db:seed`, отображение через `SAQ_DEMO_MODE=1`. В обычном режиме демо-карточки скрыты. Для удаления старых демо-данных: `node --import tsx --env-file-if-exists=.env.local scripts/clean-demo.ts`. Команда сначала сохраняет SQLite в `data/backups/`, затем удаляет только материалы демонстрационных объектов; лента соцсетей и поиски сохраняются.

Карта использует стандартные онлайн-тайлы OSM с атрибуцией. Тесты подменяют тайлы, не загружая их массово. Без сети карточки остаются доступны в списке. Публичное многопользовательское развёртывание требует авторизации, ролей, защищённого хранения и постоянного процесса сбора. Проверки государственных реестров выполняются вручную, OCR/ASR и живой ИИ без ключа не включены.

## Предварительная оценка собранных объявлений

В ленте и карточке публикации работают локальные текстовые правила `ads-1.0`: гипотеза R2 (+25) при прямом предложении оплаты/взносе с суммой, R3 (+10) при предложении покупки и явной строящейся стадии. Шкала 0–35 относится только к возможным R2/R3, не к подтверждённому риску ЖК. R1 и R4–R6 из рекламного текста не выводятся. Отрицания, бесплатная бронь, вторичное жильё, аренда, новости и предупреждения обрабатываются консервативно; хештеги сами по себе не дают баллы. Правила не заменяют понимание видео и могут пропускать нестандартные формулировки.

Есть категории релевантности, сортировка по предварительному баллу до разбиения на страницы, фильтр найденных признаков, точные цитаты, предупреждения об устаревшей дате/усечённом тексте. После привязки к ЖК аналитик может сохранить подобранные правилами цитаты как ручные гипотезы, а затем отдельно подтвердить/отклонить их. До подтверждения скоринг объекта не меняется. Оценки вычисляются по сохранённому тексту при чтении; новые публикации автоматически получают такую же обработку, дополнительные платные вызовы не выполняются.

В мониторинге показана сводка категорий по выбранным площадке/городу/архиву до пагинации и фильтра оценки. Подсказки сопоставления используют явные упоминания «ЖК + название» (также варианты RU/KZ); одноимённые объекты остаются отдельными кандидатами. Подсказка не создаёт связь и не начисляет баллы.

Состояние сбора показывает сохранённые публикации, очередь, выполняющиеся задания и последний успешный запуск по каждой площадке. Бюджет отображается по зарезервированным суммам (не фактическим списаниям); время освобождения — оценка для первого задания без будущих изменений. Отмена доступна только до запуска: резерв обнуляется, запись сохраняется в журнале как отменённая. Отмена задания не отключает расписание поиска.

## Адрес объявления → карта

В ленте автоматически извлекаются адреса с номером дома (типичные RU/KZ формы). Ссылка «Проверить адрес и добавить на карту» открывает `/monitoring/[id]/location`: сохранённый текст, извлечённые адреса и предварительная оценка. Если адресов несколько или город не упомянут, аналитик выбирает/вводит их явно; город поискового запроса не считается установленным местонахождением.

По кнопке «Найти координаты» сервер передаёт только адрес и город в [Photon](https://github.com/komoot/photon#demo-server). Не передаются текст рекламы, аккаунт и телефон. Запрос ограничен Казахстаном; ответы валидируются, кэшируются на 30 дней. Локальный лимит — 50 некэшированных запросов в сутки и интервал от 1,5 секунды. Автоматических повторов и фонового массового геокодирования нет. HTTPS endpoint можно заменить через `PHOTON_API_URL`. Публичный сервер не гарантирует доступность/полноту; для масштабирования нужен собственный сервис или договор с провайдером. Источник данных — © OpenStreetMap, ODbL.

На карте предпросмотра показываются варианты. Выбор для создания разрешён только при наличии улицы, совпадающего номера дома и города. Результат уровня улицы не становится точкой здания. При отсутствии точного результата доступен ручной ввод координат со ссылкой на источник. Подтверждение адреса/точки и стадии обязательно. Застройщик и БИН могут остаться неизвестными. Проверяются существующие объекты в радиусе 100 м; совпадение нормализованного адреса или расстояние менее 15 м блокирует создание дубликата и предлагает привязку к существующей карточке.

Создание объекта, источник координат и привязка неизменяемого объявления сохраняются одной транзакцией. Повторный запрос не создаёт второй объект. Строящийся объект появляется на карте; введённый — только в реестре. Правовое основание остаётся неизвестным, факторы риска не подтверждаются автоматически.

Проверка внешнего сервиса 18.10.2026: из сохранённых объявлений извлечены адреса Бурова 27/1, Михаэлиса 19, Базовая 2/7. Photon ответил HTTP 200 без совпадений на первые два адреса; отсутствие результата обработано явно. Успешный путь с точным ответом, кэш, выбор точки, атомарность, дубли и появление на карте проверяются на изолированных фикстурах. Это не подтверждение полноты геокодирования всех адресов города.

Правила `ads-1.1` расширяют явные платёжные формулировки (бронь с суммой, первый взнос, короткие предложения задатка). Категория «Неоднозначные условия» удерживает для ручной проверки упоминания рассрочки/брони/договора, даже если нет достаточных оснований для R2/R3; смешанные новости/предложения не получают автоматические баллы. Очередь `category=attention` включает явные признаки, неоднозначные условия и недостаточный текст. Для последнего отображается «Нет оценки». Это не полная рекламная библиотека соцсетей: анализируется только полученный текст; OCR/ASR и полнота охвата не заявляются. Скользящий лимит сбора $1/24 ч остаётся прежним.
