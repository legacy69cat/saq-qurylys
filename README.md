# SAQ QURYLYS

Проверка рекламы строящегося жилья в Казахстане: мониторинг публичных публикаций, карта объектов, объяснимый скоринг и документированное решение аналитика. Сайт и Telegram используют общие правила оценки объявления. Это рабочий пилот, а не автоматическое заключение о законности строительства.

**Сайт:** https://saq-qurylys-one.vercel.app · **Бот:** https://t.me/saq_qurylysbot

Сайт требует персональной учётной записи; пароль не входит в репозиторий. Бот доступен для личной переписки.

## Что работает

- Дашборд с картой OpenStreetMap/Leaflet, объектами, координатами и источниками. Подготовлена выборка 12 строящихся ЖК Усть-Каменогорска; это не полный реестр города.
- Мониторинг TikTok, Facebook, Instagram через Apify: поисковые фразы RU/KZ, очередь, расписание, импорт, дедупликация, архив и ограничения расходов.
- Текст объявления → признаки R2/R3, точные цитаты и предварительные баллы. Скриншот → распознавание через AI Gateway → проверка текста → те же правила. На сайте распознанный текст можно исправить до оценки.
- Telegram: текст и фото-скриншот, краткий отчёт, пояснения и дальнейшие шаги. Видео, голосовые, PDF и автоматическое открытие ссылок не поддерживаются.
- Карточка объекта: публикации, гипотезы ИИ, подтверждение человеком, источники, правовое основание, факторы R1–R6 и журнал действий.
- Адрес из объявления → варианты геокодирования Photon → подтверждение аналитиком → объект на карте. Неточный результат не выдаётся за координаты здания.
- Снимки с дрона: наблюдения ИИ по пяти пунктам, ручная проверка, экспорт JSON. По снимку не устанавливается наличие разрешения на строительство.
- Версионные сигнальные карточки и печать/PDF через браузер. Изменение данных не переписывает ранее созданный снимок сигнала.
- Авторизация: scrypt, роли admin/analyst/viewer, серверные сессии, ограничения запросов. Данные production — Turso; локально — SQLite.

## Запуск после клонирования

Node.js 24.15+ **ветки 24.x**, npm. Версия для CI указана в `.nvmrc`.

```bash
npm ci
cp .env.example .env.local
npm run db:setup
npm run db:import
npm run dev
```

Открыть http://127.0.0.1:3000. `db:setup` создаёт/обновляет схему (версия 6), не добавляя демообъекты. `db:import` импортирует публичную выборку `data/real-projects.json`, не обновляя существующие карточки. Для пустого реестра пропустите импорт. При обновлении не перезаписывайте свой `.env.local`.

По умолчанию локальный режим без входа (`APP_ENV=local`, `SAQ_AUTH_MODE=local`) и сервер слушает только 127.0.0.1. Этот режим предназначен для разработки. Ключи не нужны для карты, ручных проверок и текстового скоринга. Внешний сбор и ИИ включаются отдельно.

```bash
npm run build
npm start
```

## Настройки

Все секреты — в игнорируемом `.env.local` локально или Production Environment Variables в Vercel. Не используйте префикс `NEXT_PUBLIC_` для секретов.

| Переменные | Назначение |
|---|---|
| `DATABASE_PATH` | Локальная SQLite, по умолчанию `./data/saq.sqlite` |
| `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN` | Облачная БД; при заданном URL имеет приоритет над SQLite |
| `APP_ENV`, `SAQ_AUTH_MODE`, `SAQ_DEMO_MODE` | Production: `production`, `session`, `0` |
| `APP_URL` | HTTPS-адрес production для проверки origin и webhook |
| `AI_GATEWAY_API_KEY`, `AI_GATEWAY_MODEL` | Анализ текста и гипотезы ИИ |
| `DRONE_AI_MODEL` | Модель с поддержкой изображений для OCR и снимков с дрона |
| `APIFY_TOKEN`, `APIFY_WEBHOOK_SECRET`, `CRON_SECRET` | Автоматический сбор в Vercel |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET` | Telegram Bot API и защита входящих сообщений |
| `PHOTON_API_URL` | Необязательная замена HTTPS-сервиса геокодирования |

На текущем стенде проверена `google/gemini-2.5-flash`. Доступность модели и кредитов зависит от аккаунта AI Gateway. Не публикуйте ключи в чатах, коммитах или скриншотах. Ошибка провайдера не превращается в оценку «безопасно».

## Проверки

```bash
npm run check
npx playwright install chromium
npx playwright test
npm run test:auth
```

`check`: lint → TypeScript → unit/integration → production build. Playwright проверяет desktop/mobile, реальные пользовательские переходы на тестовых данных, роли и сессии. Тесты используют временную SQLite и отключённые внешние ключи; платные сервисы в CI не вызываются. GitHub Actions выполняет эти проверки при push/PR.

`npm run test:ai:live` отдельно вызывает реальную модель и может расходовать кредиты. Семь размеченных примеров проверяют цитаты, отрицания и инструкции внутри рекламы; это не измерение точности на всём рынке.

## Демонстрация обязательного кейса

Рабочая база и демо разделены. После `npm run build`:

```bash
npm run verify:case   # 8 ЖК, 12 публикаций, A=35/B=70/C=10
npm run demo          # отдельная временная база, http://127.0.0.1:3300
```

Все сведения демо вымышлены и явно помечены. Реальные ключи сбора и облачная база отключены. При остановке временная база удаляется. Для реального ИИ: `npm run demo -- --ai`; для автоматической live-приёмки через браузер: `npm run test:case:live` (требует ключ/модель, расходует кредиты). В последнем случае сохраняются видео и PDF в `test-results/live-case`.

[Матрица требований PDF → реализация → тест](docs/CASE_MATRIX.md) · [План защиты](docs/PITCH.md).

## Как считается риск

| Фактор | Вес |
|---|---:|
| R1: подтверждённое отсутствие правового основания | 35 |
| R2: предложение внести деньги | 25 |
| R3: реклама строящегося жилья | 10 |
| R4: подтверждённые жалобы | 15 |
| R5: расхождение заявленной и проверенной готовности от 20 п.п. | 10 |
| R6: подтверждённая задержка ввода | 5 |

Сумма ограничена 100. Красная зона: от 60 при одновременном R1 и R2; 25–59 и 60+ без этой пары — жёлтая. 0–24 — нижняя зона, но неизвестные данные не означают безопасность.

Объявление даёт только предварительные R2/R3 (до 35 баллов). Это **не полный риск** и не вероятность нарушения. Гипотезы не меняют подтверждённый балл ЖК до решения аналитика. Нет результата поиска в реестре ≠ нет разрешения.

## Границы пилота

Государственные реестры пока проверяются вручную; справочник источников не является API-интеграцией. Соцсети не гарантируют полный охват, OCR может ошибаться, распознавания речи нет. Сбор ограничен $1 за скользящие 24 часа и может ждать бюджета. В Vercel настроен ежедневный Cron и продолжение очереди через Apify webhook; непрерывный обход всех объявлений не заявляется. SSO/MFA, проверенное аварийное восстановление облачной БД и полноценный регламент эксплуатации остаются задачами перед широким промышленным запуском.
