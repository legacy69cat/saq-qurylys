# SAQ QURYLYS

Рабочий прототип для аналитика МИО: реестр строящихся ЖК, сохранённые источники и объяснимый приоритет проверки.

**Этап 1 выполнен:** приложение Next.js, локальная SQLite, миграция, демонстрационные данные и детерминированный скоринг. Есть компактный реестр с поиском/фильтрами и просмотр объекта с переходом к доказательствам. Редактирование, ИИ-анализ и сигнальные карточки пока не реализованы.

## Быстрый запуск

Нужен **Node.js 24.15+ ветки 24.x** и npm. Для пользователей nvm версия указана в `.nvmrc`. SQLite встроена в Node; отдельный сервер БД не требуется. Интернет нужен для установки пакетов, затем приложение работает локально без ключей/API.

```bash
git clone https://github.com/legacy69cat/saq-qurylys.git
cd saq-qurylys
npm ci
cp .env.example .env.local
npm run db:setup
npm run dev
```

Открыть [http://127.0.0.1:3000](http://127.0.0.1:3000). Пока репозиторий приватный, для клонирования нужен доступ владельца.

Для production-сборки на локальном компьютере:

```bash
npm run build
npm start
```

Сервер слушает только `127.0.0.1`: текущий прототип не имеет авторизации и предназначен для локальной демонстрации. Деплой не выполнялся.

## Данные

`DATABASE_PATH` в `.env.local` задаёт путь к SQLite (по умолчанию `./data/saq.sqlite`). Он читается и приложением, и CLI. Файл БД не входит в Git и не включается в сборку; на другом компьютере нужно выполнить `db:setup`. Сборка не создаёт и не заполняет БД автоматически.

```bash
npm run db:migrate  # применить миграции
npm run db:seed     # загрузить демоданные после миграции
npm run db:setup    # обе операции
```

Повторный seed вставляет недостающие записи, не дублирует их и не перезаписывает существующие значения. Это не команда сброса. Для чистого отдельного демо можно указать новый путь `DATABASE_PATH`.

Набор содержит 8 вымышленных ЖК, 12 публикаций, учебные правовые основания и источники с датами. `DEMO-000001` и подобные значения — намеренно не настоящие БИН. Адреса вымышлены, координаты не заданы. `example.invalid` — адреса примеров, они не открывают реальные публикации; сохранённый текст доступен в карточке. Время хранится в UTC, отображается в Asia/Almaty.

## Проверка сценариев

1. Откройте реестр и выберите «Контур 01»: A, 35, жёлтый. Основание неизвестно и не даёт R1.
2. Откройте «Контур 02»: B, 70, красный. R1+R2+R3 подтверждены в демоданных. По ссылке «Источник» можно перейти к сохранённому фрагменту.
3. Откройте «Контур 03»: C, 10, зелёный. Действующая учебная гарантия не превращается в R1.
4. «Контур 04» имеет 65 баллов, но остаётся жёлтым без R1. «Контур 05» имеет только гипотезы и 0 баллов. «Контур 06» показывает все факторы и 100 баллов.
5. Проверьте поиск, фильтр по зоне, пустую выдачу и сброс.

Балл считается заново при чтении данных. В расчёт входят уникальные подтверждённые факторы с источником, автором и датой проверки. Для R1 дополнительно проверяется статус основания; для R5 — обе оценки готовности и порог 20 п.п. Гипотезы начисляют 0. Красная зона требует не только 60+, но и R1+R2.

## Проверки качества

```bash
npm run lint
npm run typecheck
npm test
npm run build
# Или все четыре команды:
npm run check

# Браузерные проверки (первый раз установить Chromium):
npx playwright install chromium
npm run test:e2e
```

`test:e2e` собирает production-версию и запускает её на порту 3100 с отдельной БД `data/e2e.sqlite`; порт должен быть свободен. Тесты не изменяют пользовательскую БД. Скриншоты и трассы ошибок находятся в `test-results/` и не коммитятся.

Проверено 14 октября 2026 на Node 24.15.0 / npm 11.12.1: **51 модульный/интеграционный тест, 4 браузерных теста** (desktop и mobile), линтер, TypeScript и production-сборка. Автотесты покрывают A/B/C, границы зон, нехватку доказательств, порог готовности, идемпотентность seed, транзакционный откат, внешние ключи и сохранение данных после переподключения. Браузер проверяет API → реестр → объект → источник, фильтры и пустую выдачу.

Автоматический CI пока не включён: текущий GitHub-токен не имеет права `workflow`. Готовый [шаблон GitHub Actions](docs/examples/github-actions-ci.yml) можно перенести в `.github/workflows/ci.yml` после предоставления этого права. Все проверки доступны локально.

## Структура

```text
src/domain/risk.ts       # чистый расчёт риска и объяснения
src/server/db/           # подключение, SQL-миграция, seed, чтение данных
src/server/projects.ts   # серверная граница доступа к БД
src/app/                 # страницы и read-only API
src/components/          # общие компоненты интерфейса
scripts/database.ts      # CLI миграций и seed
tests/                   # Vitest и Playwright
```

Стек: TypeScript, Next.js 16.4.0, React 19.3.1, `node:sqlite`, Vitest, Playwright, ESLint. Версии зафиксированы в `package-lock.json`. Источники API: [Next.js](https://nextjs.org/docs/app/getting-started/installation), [SQLite в Node.js](https://nodejs.org/download/release/latest-v24.x/docs/api/sqlite.html).

Read-only API: `GET /api/projects` возвращает данные реестра и расчёт; `GET /api/health` проверяет доступ к схеме БД. При неподготовленной БД главная страница показывает команду настройки, API возвращает 503. Пустая подготовленная БД является допустимым состоянием.

## Ограничения и следующие шаги

- Нет ручного ввода рекламы, реального ИИ-анализа, OCR, изменения факторов через интерфейс, журнала действий и выгрузки сигналов.
- Подтверждения в seed заранее заданы для тестов. Это не результаты реального анализа и не ответы подключённой модели.
- Для разработки использовались инструменты генерации кода; продуктовый LLM-провайдер пока не выбран и ключи не нужны.
- Синхронная SQLite и чтение полного набора подходят для небольшого локального демо; перед ростом объёма нужны пагинация и оптимизация запросов.
- На узком экране таблица прокручивается горизонтально. Цвет зоны всегда дублируется текстом.
- Прототип не устанавливает нарушение и не отправляет материалы в госорганы.

Следующий этап: ручной ввод и привязка публикаций, полноценная карточка с метаданными проверки; затем настоящий ИИ-анализ с цитатами и подтверждением аналитика.
